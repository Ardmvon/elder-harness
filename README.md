# 银龄专线

面向老年人的 Android 接线员原型：**老人用手机的时候**，它当场帮着把事办成；遇到不确定或需要本人授权的步骤，停下交给老人自己。它以办成事和获得可信真人帮助为目标，不提供 AI 陪聊。

**它不声称 24 小时看护。** 国产系统不会给第三方应用系统进程般的待遇：重启后无障碍服务会被系统摘掉、后台会被限制。所以"一直盯着"这类承诺在这里不可信，产品也不做这种承诺（详见下面「它能承诺什么」）。

## 工作方式

1. 对着首页中央的大圆按钮**说一句话**（识别在服务端，见「老人端界面与语音」），或打字；并开启悬浮窗和辅助功能权限。
2. 悬浮接线台跟随其他应用。云端规划器收到**持续累积的对话记录**（目标、已观察的页面、已执行的操作与结果），每次可请求**一个或多个工具**；执行后新页面自动回灌，再决定下一步。
3. 点击类操作直接执行；**确认边界是可逆性，不是"有没有碰屏幕"**（详见 `docs/status.md` 的"交互与确认边界"）。
4. 模型不再请求工具时任务结束。中途停下（需要老人自己做、提问、找家人）之后再继续时，**从同一段对话接着走**，不会从头重新规划。

### 什么会停下来问老人

| 情况 | 处理 |
|---|---|
| 有文字的普通操作（点击、输入、滚动、返回、打开应用…） | 直接执行；服务端仍会拒绝付款/验证码/密码/身份/删除等目标 |
| 坐标点按（页面读不到控件，如微信、银行类应用） | 每次任务问一次，同意后不再重复 |
| 付款、结算、下单、发送、验证码、密码、身份、删除 | **不由接线员代办**：动作被拒，面板弹出"这一步要您自己做"并点名要按的按钮，老人做完点"我做好了，继续" |
| 说"办好了" | 必须先过一道**机械校验**：声明的文字要真的在本轮输入过、引用的时刻不能早于本轮开始、声称改变就得有改变类动作。不通过就不说"完成"，改成"我没法确认…"，把决定权交回老人 |
| 需要家人 | `handoff` → 首页与面板提供拨打家人电话、发送包含任务与卡点的短信 |
| 老人想中止 | 悬浮面板上一直有"停下来" |

屏幕内容通过无障碍服务读取；密码输入框不会纳入观察。当前页面的可见文字会发送至用户配置的模型服务，试用时请勿使用真实敏感信息。

## 它能承诺什么，不能承诺什么

| | |
|---|---|
| **能**（在场时）| 老人正拿着手机、或正让它办事时，观察、操作、留痕都可靠：常驻前台服务把进程钉住，无障碍掉线会被看门狗发现并提醒，无障碍被系统重新绑上时自动恢复守护 |
| **不能**（不在场时）| 持续看护。实测在这台 ColorOS 手机上：**重启后开机广播收不到**，**无障碍服务被系统从启用列表移除**（这是系统的安全设计，防止恶意应用长期持有无障碍权限）。应用既无法自我修复，也不该假装可以 |

所以"平安确认"是**和家人的约定**，不是系统能力：

> 每天会收到一条"报平安"（默认 9 点前，有活动就报"今天几点用过，一切正常"；到点还没活动就发提醒）。
> **收不到这条消息，就打个电话。**

这条约定的意义在于**沉默的含义被翻转了**：不是"没消息 = 没事"，而是"没消息 = 该确认一下"。手机没电或服务被杀时，缺的这条消息本身就是信号。

## 老人端界面与语音

一屏一件事：首页中央只有一个**大圆形按钮**，上方一行状态，下方一行提示；只有需要老人做决定时才弹出卡片。配置收进"家人设置"（右上角淡色齿轮）。圆圈的颜色就是信号：**绿＝空闲，橙＝麦克风开着**。

**像打电话，不像对讲机。** 点一下开始，之后是一次持续对话：

| 情况 | 表现 |
|---|---|
| 说完一句 | 自动结束并识别，**不用再点一下** |
| 助手正在说话时插话 | **立刻闭嘴**转听你说（打断 / barge-in） |
| 想补充一句 | 麦克风还在听，直接说（对话窗口；20 秒没人说话自动关麦） |
| 助手做的每一步 | 都念出来（"正在打开微信"），不只念结论 |
| 悬浮窗里 | 面板底部一直有「说一句话」，与首页**共用同一个麦克风会话** |

**实测的平台事实（ColorOS）**：

- **语音识别不在系统 API 里**：这台手机没有注册 `RecognitionService`（`SpeechRecognizer.isRecognitionAvailable` 为 false），也没有 `RECOGNIZE_SPEECH` 的 Activity；语音输入只存在于输入法键盘与小布助手中。所以识别走**我们自己的服务端**（讯飞听写），手机只负责录音与播放。
- **语音播报可用，但必须声明 `<queries>` 里的 `TTS_SERVICE`**：否则 Android 11+ 的包可见性会让应用连引擎都绑不上，表现就像"这台手机没有语音引擎"——我们一度据此下了错误结论。
- 没有识别能力时，圆按钮显示"打字或说话"，点开即聚焦输入框，可以用**键盘上的话筒**说话。

## 家人与社区（可信的人）

老人遇到办不了的事，不该只有"自己想办法"这一个选项。手机可以配对一个**可信圈子**：家人、社区网格员、邻居各自登记身份，出事时在**一个网页**上看到情况并接手——他们不用装应用，老人也不用多给一个权限。

服务端在 `server/`（Python + FastAPI + SQLite），本地跑：

```bash
cd server
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8787
```

手机端在「设置 → 家人与社区」里填服务器地址、点配对，把 6 位配对码告诉家人；家人打开 `http://<服务器>/` 输入配对码即可。

**三条规矩**（也是这个模块的全部意义）：

| 规矩 | 为什么 |
|---|---|
| **角色决定能看到什么** | 家人看全部；社区看求助与异常；邻居只在需要人上门时看到。"老人在做什么"这类上下文**只给家人**——页面文字里可能有姓名、地址、验证码 |
| **只有家人能给老人留话** | 那个渠道在老人手机上读起来是熟悉的人在说话，不能让名单外的人借用 |
| **不做远程控制** | 只给状态和请求。远程协助/屏幕共享正是我们要防的诈骗手法，做了就再也分不清自家通道和骗子的通道 |

**语音识别也走这台服务端**：手机上传一段 16 kHz 单声道 PCM，服务端用讯飞听写转文字（`/api/device/transcribe`；是否可用见 `/api/speech/status`）。**讯飞密钥只存在服务端**的 `server/.env`（已 gitignore）：不进 APK、不进仓库，手机丢了也不泄露密钥。只想验证协议的话，服务端有纯函数测试，不需要网络。

**M1 的范围**：配对、圈子名单（家人/社区/邻居+角色）、求助（带上下文）、报平安与异常上报、家人网页（看状态/认领求助/留话）、**服务端心跳与失联判定**（手机关机/没电/被杀时，只有服务端能发现）、以及服务端转写的语音识别。

**M1 故意不做的**：短信通知（`server/app/notify.py` 现在只写日志，真实短信要服务商与模板审核）、账号密码、社区派单/值班、以及老人手机上的大字卡片+语音（M2）。

## 构建和试用

需要 JDK 17、Android SDK 35。执行 `./gradlew :app:assembleDebug`，安装 `app/build/outputs/apk/debug/app-debug.apk`。应用设置中填写家人电话号码、兼容 OpenAI Chat Completions 且支持 tool calling 的 HTTPS 地址、模型名和访问密钥。

**访问密钥用 Android Keystore 加密后存在本机**（`SecretStore`）：家人配置一次即可，重启、被杀掉、重启手机之后仍然可用——否则每次重启都要有人在那台手机上重新输入 35 位密钥，而老人做不到这件事。密钥不写进对话记录、不写进任务存档、也不写进日志（日志只记"已设置"与长度）。换手机需要重新填写。

在手机上打开应用，按提示开启悬浮窗和辅助功能（**麦克风权限需要手动允许一次**，系统会弹窗）。说出目标后应用退到后台，悬浮接线台会显示进度（工作时显示"正在办 N"，需要老人时自动展开）。点按胶囊可展开：确认一步、暂停、联系家人，或直接说话。

本地联调（服务端跑在本机）时，用 adb 把端口反向映射即可，不需要同网段：

```bash
adb reverse tcp:8787 tcp:8787     # 手机上的 127.0.0.1:8787 指向本机；重新插拔 USB 后要重设
```

**调试通道与演示模式是两个开关**：`developer_mode`（adb 传参 + 写 `files/loop.log`）与 `auto_confirm`（界面标为"演示模式"，自动确认一切）。分开才能在开着调试通道的同时测出真实使用时老人会被问什么：

```bash
adb shell am start -n com.yinling.hotline/.MainActivity \
  --ez developer_mode true --es apikey "$KEY" --es model deepseek-chat \
  --ez dev_mode false --ez clear_log true --ez start true \
  --es goal "打开喜鹊儿，看看我明天有什么课"
```

## 任务续办与缓存

每个任务（session）落盘在 `files/sessions/<id>.json`，保留最近 5 个。老人被打断、应用被杀掉或重启后，首页"上次没办完的事"里可以直接**接着办**：恢复的是**模型此前看到过的同一份对话**，因此请求前缀不变，模型服务的前缀缓存继续命中。

实测（deepseek-chat，喜鹊儿/美团真实任务）：

| 场景 | 输入 tokens | 缓存命中 | 命中率 |
|---|---|---|---|
| 首轮 | 2329 | 0 | 0% |
| 第 2 步 | 2419 | 2176 | 89% |
| 第 3 步 | 3622 | 2432 | 67% |
| 中断前第 5 步 | 5610 | 4096 | 73% |
| **恢复后第 1 步** | 6183 | 5760 | **93%** |
| 恢复后第 2 步 | 6254 | 6016 | **96%** |

两条设计约束由此而来：

- **对话只追加、不重写**。实测把 system 指令改动一个字，命中率就从 68.6% 掉到 3.6%。
- **恢复必须还原原文**。只要消息内容或顺序变了，缓存前缀即失效。截图（base64）不入盘，恢复后由下一步重新观察。

## 任务如何收尾

模型有五种明确的收尾方式，互不混淆：

| 方式 | 含义 | 老人看到 |
|---|---|---|
| 不再请求工具（普通回答） | 事情办成了 | 已完成 |
| `impossible(reason)` | 确认这件事在手机上做不到（功能不存在、平台限制、需本人身份） | 做不到 + 原因 |
| `ask_person(reason)` | 这一步必须老人亲自做（付款、发送、验证码、密码） | 等您操作 |
| `ask_user(question, options)` | 需要老人补充信息，问完等待回答；选项做成按钮，点一下即可 | 等您回话 |
| `handoff(reason)` | 需要家人帮忙 | 找家人 |

`ask_user` 的回答由主界面的"回答接线员"输入框、悬浮窗上的选项按钮或语音给出，作为一条消息追加进对话后继续，任务不会重新开始。

把"做不到"和"已完成"分开是刻意的：对依赖这个结果的老人来说，把做不到说成完成是最有害的一种错误。

## 经验技巧（skill）

第三方应用的专属知识**不写进 system prompt**，而是做成按需加载的技巧：技巧名与用途出现在 `load_skill` 工具说明里，模型需要时调用 `load_skill`，详细步骤作为工具结果进入对话；当前前台应用匹配到某个技巧时，页面文本末尾追加一行提示。

**触发推送，方法拉取**：模型不知道自己该去查技巧，所以"什么情况查哪个技巧"写在系统指令里；而"具体怎么做"放在技巧里。两者不能重复——指令里把方法写全，技巧就没人读（实测 `load_skill` 调用 0/4；只留触发对照后 3/3，任务读对率 2/4 → 3/3）。

当前六条：`reading_tables`（读表格/课表，防止读错列）、`canvas_content`（信息在图形里）、`blind_page`（页面读不到控件）、`wechat_input`（微信里输入文字）、`find_target`（找不到控件）、`tool_errors`（工具报错）。

## 代码分工

- `core/AgentLoop.kt`：**与 Android 无关的循环**。持有对话记录，逐轮生成、本地校验、审批（可原地恢复）、执行、回灌观察；含网络退避重试、停滞与动作周期检测、步数上限，以及"需要老人自己做"的标记。`AgentPlanner`、`AgentTools`、`ActionApproval` 是替换点。
- `core/PhoneTools.kt`：页面数据结构、工具调用/结果类型，以及工具目录 `PhoneToolCatalog`（模型看到的唯一动作集合）。
- `app/CloudPlanner.kt`：OpenAI 兼容的 tool calling 规划器。只负责协议转换与错误分类（可重试/不可重试），不做安全判断。
- `app/ScreenAccessService.kt`：通用 Android 页面观察与执行，不包含任何第三方应用脚本。页面 revision 绑定、敏感页与拒付词表、越界检查都在这里。
- `app/AndroidPhoneTools.kt`：把页面观察与具体应用启动、等待、系统导航接起来。
- `app/SessionController.kt`：任务状态机、跨暂停保留 loop 实例、确认策略、家人交接。
- `app/SessionStore.kt`：任务落盘与恢复。保存时丢弃截图，只保留文本对话，以便恢复后缓存前缀不变。
- `app/SkillCatalog.kt`：按需加载的经验技巧，把第三方应用的专属知识挡在 system prompt 之外。
- `app/MainActivity.kt`、`app/OverlayService.kt`：老人端首页、设置与跨应用悬浮接线台。

## 回归校验

```bash
harness/run.sh
```

JVM 上对着严格校验 transcript 的 mock 提供方跑 **73 项**检查（循环、协议、审批、停滞与循环检测、观察层呈现、收尾语义、结果校验）；服务端另有 **20 项** pytest（配对/心跳/失联/认领/角色边界/转义/语音协议解析）。**Android 侧没有自动化测试**，只能在真机手工验证——语音链路就是靠真机日志逐条确认的。详见 `harness/README.md` 与 `server/README.md`。

## 已知边界

这是可试用的架构原型。

- **成功后仍无证据层校验**：已有机械层（声明的文字要真的输入过、引用的时刻不能早于本轮开始、声称改变就得有改变类动作），它能否掉"物理上不可能"的谎报，但挡不住"确实动了手却没做成"。下一步是让第二个模型比对前后截图。
- 密集表格（课表）可能读错列：已有 `reading_tables` 技巧，样本仍小。
- 坐标点按（页面读不到控件时的兜底手段）无法做内容校验，护栏是每次任务开始时的一次确认。
- 上下文随步数线性增长（10 步约 4 倍），暂无压缩策略。
- **重启后无障碍服务会被系统移除、开机广播不保证送达**（实测 ColorOS）。应用内的保活只覆盖"在场时"：常驻前台服务、掉线看门狗、无障碍重新绑定时的自愈钩子。跨重启的可靠看护需要外部观察者（家人按约定打电话，或服务端心跳）。
- 家人端只有短信与电话，尚无独立客户端；「报平安」也走短信。
- 微信等应用屏蔽无障碍读取，只能靠截图 + 按比例坐标点按；文字输入依赖"剪贴板 → 输入法候选栏"这一取巧路径，换输入法可能失效。
- 强制停止应用后，辅助功能服务有时需要重新开启才能继续。
- **`DecisionCache`/`RecipeCache` 目前是死代码**：`AgentLoop` 只声明了接口，从未调用 `suggest/remember`；且实现是进程内 map、键里含每次都会变的 `revision`，即使接上也不会命中。
- **语音识别依赖网络与服务端**：讯飞听写是云服务，断网即不可用；这台手机没有系统识别能力，所以离线场景只能用键盘话筒或打字。语音识别也不在本地留存（录到的 PCM 只在内存里转成文字）。
- 麦克风在对话期间持续开启（20 秒无人说话自动关闭）。阈值是手工调的（门限 1400，实测人声 2300~5200，静音判定 900 ms），嘈杂环境可能误触发。
- 每次观察会把当前页面文字发给模型服务；页面元素较多或带截图时单次请求仍然偏大。
