# 回归校验（harness）

跑在 JVM 上的循环与协议回归检查：`core/` 的循环 + `app/CloudPlanner` 的协议转换，对着一个
**严格校验 transcript 的 mock 提供方**运行。

```bash
harness/run.sh          # 全通过时退出码 0
```

前置：JDK 17、`python3`，以及 Gradle 能解析项目依赖。脚本通过 `:harness:run` 编译，使用临时端口启动 mock 服务，不再手工拼接本机缓存 jar。

## 为什么要有它

transcript 的结构合法性是硬约束：每个 `tool_calls` 都必须有对应的 `tool` 回复、参数类型要对、
角色顺序要对。违反它，真实提供方会直接 HTTP 400 —— 这个错误在开发中**出现过四次**，而且每次都是
运行时才发现。`mock_server.py` 就按真实提供方的规则校验，把这类问题挡在提交之前。

## 覆盖范围

| # | 检查 | 关注的失效模式 |
|---|---|---|
| 1 | 多工具调用 + 批准 + 自然结束 | 正常一轮 | 
| 2 | 服务端 503 自动重试 | 网络退避不能变成任务失败 |
| 3 | 未知工具 → 回传清单，可修复 | 模型编造工具名时不要整批丢弃 |
| 4 | `handoff` → 交家人 | 收尾语义 |
| 5 | 纯数据工具重复读取被拦 | 重复调用不算进展 |
| 6 | `impossible` → 明确做不到，而不是已完成 | 最有害的一类错误 |
| 7 | `ask_person` / `ask_user` 是独立收尾 | 收款/提问/家人不能混 |
| 8 | 回答后继续 | 回答要进对话且不重开任务 |
| 9 | 滑动条会被呈现给模型 | 观察层缺失（"模型不会用"常常是没给它看）|
| 10 | 无标签的可操作叶子会被列出（带位置）| 同上，图标/格子类控件 |
| 11 | 在两个页面之间来回切换会被停下 | 页面指纹检测不到的循环 |
| 12 | 显式截图会被送到下一轮请求 | 图片曾静默丢弃 |
| 13 | 连续查阅不会被误判为停滞 | `current_time`/`load_skill` 不改变页面 |
| 14 | 进入→退出的循环会被停下 | 动作周期检测（周期 2/3）|
| 15 | 重复单一动作不会被当成循环 | 退格键、翻页是合法的 |
| 16 | 逐个填表的周期性操作不会被拦下 | 合法周期不能被误伤 |
| 17 | 宿主缩小确认范围后不再逐步打扰 | 确认边界 = 可逆性 |
| 18 | 需要老人自己做的步骤会带标记 | 悬浮窗据此展开"这一步要您自己做" |
| 19 | 结果声明与真实输入 payload 对齐 | 参数顺序、收件人与正文混淆、旧证据不能冒充本轮输入 |
| 20 | 输入文字不等于发送/支付/提交成功 | 没有独立效果证据时拒绝虚假完成 |
| 21 | 只有观察没有改变却声称完成 | `OutcomeCheck` 拒绝无状态变化的声明 |
| 22 | `type_text` / `paste_text` / `input_text` 风险词 | core 在审批前拦截，0 次执行并返回 `PAUSED(needsPerson=true)` |

## 不覆盖什么

Android 相关的路径**无法在这里验证**，只能在真机上手工测（`docs/status.md` 里记了实测结果）：

- 辅助功能服务的页面观察与执行（`ScreenAccessService`）
- 截图管线（分辨率/无损 WebP/后台编码）
- 悬浮接线台的布局、动画、点击
- 任何第三方应用的真实行为

## 目录

- `Harness.kt`：检查本体，用假的 `AgentTools`/`AgentPlanner`/`ActionApproval` 驱动循环
- `mock_server.py`：mock 的 OpenAI 兼容端点，校验 transcript 后返回预设动作
- `run.sh` / `run.py`：构建 harness、起临时端口 mock、跑检查并传递退出码
